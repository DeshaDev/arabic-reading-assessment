# نَبراس — مختبر القراءة العربية

منصة ويب تجريبية تساعد المعلم على تنظيم جلسة قراءة عربية، تسجيل إجابات الفهم، ومراجعة مؤشرات وصفية من الجلسة. المشروع ما زال نموذجًا أوليًا، وليس منتجًا سريريًا أو أداة معتمدة للكشف عن عسر القراءة.

## ما يعمل في هذه النسخة

- لوحة RTL متجاوبة تعرض السجلات والجلسات الموجودة فعلًا في ملف البيانات، وتعرض حالة فارغة واضحة عند عدم وجود بيانات.
- إدارة سجلات الطلاب مع تحقق أساسي من الحقول والبحث والتصفية حسب الصف.
- مكتبة نصوص وأسئلة فهم عربية متدرجة للصفوف 1–6.
- بروتوكول من سبع مراحل: التهيئة والمعايرة الاختيارية، تسمية حروف عربية موقّتة، قراءة جهرية، أسئلة فهم، ملاحظات المعلم، قراءة ثانية من نص بديل، ثم ملخص وصفي.
- رسم مسار النظر/الخريطة الحرارية داخل الجلسة الحالية عند توفر عينات كافية بعد المعايرة.
- مؤقتان لمقطعي القراءة، وتسمية حروف عربية موقّتة، ووسم يدوي للكلمات (خطأ/استبدال، حذف، تردد، تصحيح ذاتي)، إضافة إلى الأسئلة وملاحظة استقلال القراءة والمساعدة.
- تسجيل صوت اختياري للمقطع الجهري يبقى في المتصفح افتراضيًا. التحليل الآلي لا يبدأ إلا بعد موافقة منفصلة؛ يُرسل الصوت حينها إلى واجهة التفريغ الصوتي، ولا يُحفظ ملف الصوت في قاعدة بيانات نَبراس. يُحفظ نص التفريغ ونتيجة المقارنة فقط في ملف قاعدة بيانات نَبراس على الخادم، ولا تُحفظ بايتات الصوت فيه.
- تقرير قابل للطباعة أو الحفظ بصيغة PDF، بلغة لا تصف الطفل بأنه مصاب بعسر القراءة.
- محرك تفريغ عربي اختياري عبر OpenAI Audio Transcriptions API، ومحاذاة كلمة بكلمة مع النص المرجعي لاستخراج فروق محتملة (استبدال/حذف/إضافة/تكرار).
- تحفظ واجهة التحليل مفتاح API على الخادم فقط، وتحدد حدًا لحجم الصوت ومعدل الطلبات، ولا تحفظ بايتات الصوت. الفروق الآلية تحتاج مراجعة بسبب احتمالية أخطاء التعرف الصوتي.

## تشغيل محليًا

يتطلب Node.js بإصدار يدعم اختبارات node:test.

~~~bash
npm install
npm start
~~~

ثم افتح http://127.0.0.1:3000.

لتشغيل اختبارات المحرك:

~~~bash
npm test
~~~

يمكن تحديد المنفذ عبر PORT والمضيف عبر HOST. افتراضيًا يستمع الخادم على 127.0.0.1 حتى لا ينكشف على الشبكة المحلية دون قصد. لا تغيّر HOST إلى 0.0.0.0 إلا إذا كنت تدرك تبعات تعريض الخادم.

## تفعيل تحليل القراءة الجهرية آليًا

تعتمد الميزة على خدمة تفريغ خارجية اختيارية؛ لا تحتاج إلى تثبيت مكتبة إضافية ولا يظهر مفتاح الخدمة في المتصفح. تحتاج إلى مفتاح API صالح وإعداد الفوترة لدى المزوّد، وتُرسل التسجيلات فقط عند الموافقة داخل شاشة النتيجة والضغط على **تحليل القراءة آليًا**.

اختر نموذج التفريغ عبر `OPENAI_TRANSCRIPTION_MODEL`; الافتراضي `gpt-4o-mini-transcribe` ويمكن ضبط `gpt-4o-transcribe` عند الحاجة. لا تضف المفتاح إلى ملفات JavaScript أو HTML أو المستودع.

**Windows PowerShell:**

~~~powershell
$env:OPENAI_API_KEY = "ضع-مفتاحك-هنا"
$env:OPENAI_TRANSCRIPTION_MODEL = "gpt-4o-mini-transcribe"
npm start
~~~

**macOS / Linux:**

~~~bash
export OPENAI_API_KEY="ضع-مفتاحك-هنا"
export OPENAI_TRANSCRIPTION_MODEL="gpt-4o-mini-transcribe"
npm start
~~~

بعد إعادة تشغيل الخادم، ابدأ جلسة جديدة، فعّل تسجيل الصوت الاختياري في مقطع القراءة الجهرية، وأكمل الجلسة. في شاشة الملخص، وافق على إرسال التسجيل ثم اضغط **تحليل القراءة آليًا**. إذا لم يكن المفتاح مضبوطًا، ستظهر رسالة توضيحية بدل نتيجة وهمية.

طريقة العمل: يرسل الخادم الصوت إلى [واجهة OpenAI لتفريغ الصوت إلى نص](https://platform.openai.com/docs/api-reference/audio/createTranscription) باللغة العربية، ثم يحاذي التفريغ مع النص المستهدف باستخدام مسافة تحرير على مستوى الكلمات. يصنّف المحرك الفروق إلى استبدال أو حذف أو إضافة أو تكرار، ويعرض نسبة اختلاف تقريبية. هذه **فروق في تفريغ الكلام** وليست أخطاء قراءة مؤكدة؛ فقد ينتج بعضها عن التشكيل أو اللفظ أو اللهجة أو نموذج التعرف. لا يقدم المحرك ثقة كلامية موثقة ولا يحدد توقيت كل خطأ داخل التسجيل.

الأصوات المرسلة قد تخضع لمعالجة مزوّد الخدمة وسياساته. احصل على موافقات ولي الأمر والمدرسة والطفل بحسب المتطلبات المحلية، واستخدم رموزًا داخلية بدل أسماء حقيقية. لا تستخدم النسخة الحالية لخدمة عامة أو تخزين بيانات أطفال حساسة قبل إضافة المصادقة والصلاحيات وحوكمة البيانات.

## تجربة الواجهة على GitHub Pages

الواجهة تحتوي على وضع تجريبي ثابت لا يحتاج إلى Express:

- بعد تفعيل GitHub Pages من **Settings → Pages → Build and deployment → Source: GitHub Actions**، ينشر الملف `.github/workflows/pages.yml` محتويات `public/` تلقائيًا مع كل تحديث مناسب على `main`.
- رابط المشروع المتوقع: `https://deshadev.github.io/arabic-reading-assessment/`.
- تبدأ التجربة بسجل افتراضي باسم «طالب تجريبي». أي سجلات أو جلسات تضيفها تُحفظ في `localStorage` على المتصفح نفسه، ولا تُزامَن إلى الخادم أو إلى أجهزة أخرى. زر «مسح بيانات التجربة» يمسح هذه البيانات.
- لا تدخل أسماء أو بيانات أطفال حقيقيين في النسخة العامة.
- يمكن تجربة التنقل، مكتبة النصوص، الأنشطة، جلسات القراءة والملخصات. يظل تحليل الصوت الآلي غير متاح على Pages؛ فهو يحتاج إلى خادم منفصل يحمي مفتاح API. وضع Pages يعترض مسارات API محليًا ولا يرفع التسجيل الصوتي.
- تشغيل الخادم محليًا مع `npm start` لا يدخل في وضع Pages، ويظل مسار API المحلي متاحًا وفق إعداداته.

**خطوة إعداد لمرة واحدة:** أول تشغيل لعملية النشر لا ينجح إذا لم يكن الموقع مفعّلًا بعد. افتح [إعدادات GitHub Pages للمستودع](https://github.com/DeshaDev/arabic-reading-assessment/settings/pages)، واختر `GitHub Actions` مصدرًا للنشر. بعد ذلك أعد تشغيل `Deploy GitHub Pages demo` من تبويب Actions أو ادفع تحديثًا إلى `main`.

## المسار البحثي الذي يستند إليه النموذج

المراجع التالية تساعد على فهم جدوى التقنية وحدود نقل نتائجها. وجود أبحاث لا يعني أن هذا المستودع أصبح أداة معيارية أو مكافئة لمنتج تجاري:

- [Ikermane & El Mouatasim (2023), Dyslexia deep clustering using webcam-based eye tracking](https://doi.org/10.11591/ijai.v12.i4.pp1892-1900) — دراسة على 61 تلميذًا من ثلاث مدارس ابتدائية مغربية، تناولت تتبع النظر عبر كاميرا الويب أثناء القراءة العربية. هذه إشارة إلى جدوى بحثية عربية تستحق المتابعة، وليست وحدها تحققًا خارجيًا كافيًا لنظام فرز واسع النطاق.
- [Webcam-based eye tracking to detect mind wandering and comprehension errors](https://pubmed.ncbi.nlm.nih.gov/36627435/) — دراستان على مشاركين بالغين استخدمتا WebGazer في مهام فهم القراءة باللغة الإنجليزية. تفيد في فهم قابلية التقنية للدراسة عن بعد، لا في إثبات دقة كشف عسر القراءة بالعربية.
- [Lexplore: assessment with webcam](https://info.lexplore.com/en/support/how-to-run-an-e-assessment) و[متطلبات التقييم عبر الويب](https://info.lexplore.com/en/support/technical-requirements-for-e-assessment) — توثيق عام لسير التقييم وملاحظات الجهاز والمعايرة والقراءة الجهرية/الصامتة وأسئلة الفهم.

تستلزم الجاهزية العربية المستقلة دراسة تحقق على عينة ممثلة، ومعيارًا مرجعيًا مستقلًا لصعوبات القراءة، وتثبيت بروتوكول القراءة، وتقييم الحساسية والنوعية والقيم التنبؤية، واختبارًا خارجيًا على مدارس وأجهزة لم تدخل في التطوير. لا يحتوي هذا المستودع على مجموعة بيانات موسومة كافية أو نموذج تعلم آلي مدرّب ومتحقق منه؛ لذلك لا ينتج تصنيفًا آليًا لعسر القراءة. أضيف الآن تفريغ الكلام الجهري ومحاذاة النص، وليس نموذجًا معتمدًا للتعرف على كل خطأ قراءة.

## حدود مهمة قبل الاستخدام الميداني

- **لا يوجد تشخيص لعسر القراءة.** لا ينتج النظام درجة خطر تشخيصية، ولا يثبت أن الطفل لديه صعوبة تعلم أو لا يعاني منها.
- **تتبع النظر تجريبي.** تقدير اتجاه النظر عبر كاميرا ويب عادية يتأثر بالكاميرا والإضاءة ووضعية الرأس والشاشة، ولا توجد في هذا المستودع دراسة تحقق سريري تثبت صلاحيته لعسر القراءة باللغة العربية.
- **المعايرة ليست قياسًا للدقة.** إكمال نقرات نقاط المعايرة لا يعني أن دقة النظر قد تم التحقق منها علميًا.
- **سرعة القراءة ليست معيارًا منفردًا.** لا يحسب النظام السرعة إذا كانت الجلسة قصيرة جدًا أو كان الناتج خارج فحص الجودة التقني؛ ويجب تفسير النتائج في سياق تعليمي أوسع.
- **لا تستخدم بيانات أطفال حقيقية في نسخة عامة أو غير محمية.** الخادم لا يحتوي على تسجيل دخول أو صلاحيات أو تشفير للبيانات المخزنة. الأسماء والملاحظات وملخصات الجلسات تُكتب في المسار data/database.json. قبل تجربة مدرسية، يجب إضافة المصادقة والتحكم في الوصول وموافقة المدرسة/ولي الأمر وسياسة احتفاظ وحذف بيانات مناسبة.
- إحداثيات النظر الخام لا تُحفظ على الخادم، لكنها تُستخدم مؤقتًا في ذاكرة المتصفح لرسم المسار داخل الجلسة. وقد تسجل كاميرا الطفل بيانات حساسة؛ اشرح ذلك واحصل على الموافقات المناسبة.

## البنية

- server.js — Express API محلي للسجلات والملخصات؛ بوابة التفريغ الصوتي تحفظ المفتاح على الخادم.
- lib/reading-alignment.js — محاذاة التفريغ العربي بالنص المرجعي على مستوى الكلمات.
- test/reading-alignment.test.js — اختبارات التطبيع والمحاذاة والاستبدال والحذف والتكرار.
- public/index.html وpublic/css/style.css — واجهة RTL المتجاوبة.
- public/js/dashboard.js — اللوحة والسجلات والحالات.
- public/js/assessment.js — سير الجلسة والمعايرة والقراءة والفهم.
- public/js/tracker.js — تكامل WebGazer وإشارة الكاميرا.
- public/js/metrics.js — استخراج مؤشرات وصفية وفحوص جودة بسيطة، دون معايير تشخيصية.
- public/js/report.js — ملخص الأسرة والطباعة.
- public/js/texts.js — بنك النصوص وأسئلة الفهم.
- test/metrics.test.js — اختبارات حدود حساب سرعة القراءة وجودة الجلسة.

## النطاق التالي قبل ادعاء الجاهزية

1. مراجعة تربوية ولغوية مستقلة للنصوص وأسئلة الفهم حسب البلد والمنهج.
2. بروتوكول قياس محدد مسبقًا، ومقارنة علمية مع أدوات عربية معيارية وبيانات ممثلة، ومراجعة أخلاقية قبل أي ادعاء حول عسر القراءة.
3. بنية بيانات آمنة بهوية وصلاحيات وسجل تدقيق وإجراءات حذف ونسخ احتياطي.
4. اختبارات فعلية عبر أجهزة وكاميرات ومتصفحات متنوعة، مع قياس معدل فشل المعايرة بدل الاكتفاء بإكمال خطواتها.
5. تقييم التعرف الصوتي على قراءة أطفال بالعربية الفصحى ولهجات مناسبة للعينة، بقياس دقة التفريغ لكل خطأ من أخطاء القراءة ومراجعة بشرية مزدوجة.
